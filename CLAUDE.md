# CLAUDE.md

`logos-ssh` (`github.com/logoscore/logos-ssh`): the SSH module, an agentless channel and its factory (docs `contracts/agentless-channels.md`, a draft until core and the docs land). Two programs, one image: `cmd/ssh-channel` (module `ssh`, a channel: both kinds `agentless`, the channel acting as the minion of the servers it logs in to) and `cmd/ssh-factory` (module `ssh`, a factory: builds with the AES suite as any factory's, a JSON description each, nothing to deploy; core keeps a build's keys and gives them to the channel with each call and open, as its kinds are agentless). The two share a module name, as the Dumbo pair do, with their own instance ids (`ssh-local`, `ssh-factory-local`). README.md has what they declare and how a call and an open go.

## Commands

```bash
go build ./... && go vet ./... && go test -race ./...
golangci-lint run --max-issues-per-linter 0 --max-same-issues 0 ./...
docker compose up -d --build
```

Go 1.25.7: pick module versions that do not need a newer Go (x/crypto v0.55.0 and x/net v0.58.0 are the last on 1.25). CI (`.github/workflows/ci.yml`, the same file as the other Go modules) runs the tests and golangci-lint v2.13.2 with default linters, no config: keep 0 issues. A `v*` tag publishes the image (`docker-image.yml`). The tests are Unix-only where they log in: `internal/sshtest` is an SSH server in the test's process (password and key logins, keepalives, `/bin/sh` commands each in a process group of its own as sshd's sessions are, signals, SFTP from a folder); `sshtest.NewWindows` answers as Windows's OpenSSH does (its version, SFTP from a request server with `C:` at the root and a link to a folder read as a junction, commands a test's `Exec` answers, its ctx ended by a signal, `Signals` counted), and `internal/sshhost`'s `fakeWindows` answers what the Host asks (cmd's `dir`, the hello's and volumes' scripts). Nothing here runs a real Windows server: check Windows changes against one by hand (a throwaway test with the server's key by path). When a change needs an unreleased protocol or channel-core, a git-excluded `go.work` (`use . ../logos-golang-protocol ../logos-golang-channel-core`) wires the checkouts, and the dev stack runs host-built binaries (`.dev-bin/`, mounted on `alpine:latest` by a git-excluded `docker-compose.override.yml`): the image builds from the tagged modules only. Drop all three at release, once the tags are in `go.mod`.

## Layout

- `internal/minion`: the SSH minion's own workings (minions share the protocol, never their insides): `Runner` for a persistent connection (BOB's minion's ways: tasks in the background, each message within the connection's size, a standing allowance; a runner lives as long as its connection, so core's `reack` gets an `ack` for its own tasks and `unknown_task` for any other), `Caller` for calls (the Dumbo page's ways: a call's tasks run in it, walks depth first and transfers going on from their `ctx`, the SHA-256's state carried in it), both acting on a `Host`; `ReadCore`/`Reply`/`Message` (a message has an `id`, starting an exchange, or a `re`, answering one, never both). Tests run it on the test's machine (`osHost`).
- `internal/sshhost`: the `Host` over SSH: files over SFTP (`fs.PathError`s, so `fs.ErrNotExist`/`fs.ErrPermission` show), a folder in name order, owners by name from `/etc/passwd` and `/etc/group` read once, a path's file system as the mount it is under (`/proc/self/mounts`, else `df`), `Rename` the POSIX way where the server has it, `WriteAt` a chunk a call; `Shell` runs `exec /bin/sh -c '<echo LOGOS-PID:$$; command>'`, stdout's first line kept back for the process group a stop kills (`kill -s KILL -- -pid` in a session of its own); `Volumes` from `df -kPT` (else `df -kP`); `Hello` from `uname -snm; id -un; id -u`, the machine id from `/etc/machine-id` over SFTP, else the host key's SHA-256 (`ssh-host-key`). A Windows server (`windows.go`, `winpath.go`; its version says `OpenSSH_for_Windows`, or SFTP's folder is a drive's, `/C:/…`) is served as BOB's minion on Windows: Windows paths for core and the minion (`winAbs`: `/` as `\`, a drive alone its root), `sftpPath` for every SFTP call (`h.remote`); each `ReadDir` also runs cmd's `dir` (`winDirCommand`, `chcp 65001`, marks between parts) beside the SFTP read for attributes (the listing's `Mode`, hidden) and junctions (links with targets: SFTP reads a junction as its folder and follows it); `Lstat` says a junction is a link; `RemoveAll` is `winRemoveAll` (enters no junction, refuses a folder it cannot tell apart); `Remove` clears read-only first; `Shell` sends the line as typed (the default shell, `cmd.exe /c "<line>"`) and stops by a `KILL` signal (Windows's OpenSSH ends the tree on it; a close alone leaves it running); `Hello` and `Volumes` run one PowerShell script each (`psCommand`: `-EncodedCommand`, constrained-language safe, values as hex of UTF-16), the hello falling back to cmd (`winHelloFallback`), the volumes to SFTP's root and `statvfs`; the machine id is BOB's on Windows (`smbios-uuid`, else `win-machine-guid`, else `ssh-host-key`).
- `internal/sshconn`: dial (direct, SOCKS5, HTTP CONNECT), log in (key first, then password and keyboard-interactive with it), check the host key, keep the first bytes for "not an SSH server"; `Failure`/`CallFailure` map what came of it onto link failures (`login`, `host_key`, `unreachable`, `timeout`, `other`) or an excerpt. `Pool` keeps a call's login for its target's `call_reuse`, checked with a keepalive before reuse. Channel opens go through `Conn.Session`/`Conn.SFTP`, never `SSH.NewSession` directly: an open waits at most `OpenWait` (15s) and gives up with the connection, as `x/crypto/ssh` can leave one unanswered for good on a connection that went away under it; `Close` ends every wait on the connection.
- `internal/agent`: `Agent.Call` (the control link's handler, within the shorter of core's deadline and the channel's `CallTimeout` (`CALL_TIMEOUT`, live as `call_timeout`, 2m, what core waits): read the target, open the message with the call's keys (`linkclient.Call.Keys`; a call without them is refused), a login from the pool, `Caller.Answer`, the reply under the call's id) and `Agent.Open` (log in, `connclient.Dial`, then a `session`: the minion speaks first, its hello alone under the id the open gives (`linkclient.Open.Under`: the target's open session's, else the build's), and goes on under the session id a `hello_response` gives; an open with no id is refused; replies match by `re`, the rest are pushes; a keepalive every `keepalive`; either side closing closes both).
- `internal/connection`: the connection schema and `ReadTarget`. `internal/ops`: the commands' numbers, shared by the factory's schema and the minion. `internal/management`: the channel's manifest. `internal/icon`: the icon both register with. `cmd/ssh-factory`: the build schema (its params numbered as the minion's `Arg…`), the builder (steps describe, upload; `ssh-<id8>.json`), management (`log_level`). The channel's management: `call_timeout` and `log_level`, live. In a call, a shell's timeout is cut to the call's deadline less `callMargin` (said "stopped at the call's deadline"), and a task after the call's first starts only with `lateStart` (5s) of the call left; else it waits, not acked, for the next call.

## Conventions

- The channel is the minion: it reads core's messages and holds targets' credentials. Never log a credential or a message's contents; logs carry the request id, the server, the outcome and the duration.
- Lifecycle, management serving and the control link's and sockets' plumbing stay in module-core and channel-core.
- Nothing may wait on a server past its context. channel-core opens the control link again only once every call returned, so one stuck call stops the whole channel: `Agent.call` closes the call's connection when its context ends (core's deadline, the link dropping), and a broken connection is never pooled.
- The tests check every item the minion sends with the protocol's own validators (`checkItems` in `internal/agent`): core refuses what they refuse.
